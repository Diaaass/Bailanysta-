# 0006. Гибридный поиск с порогом, выведенным из замеров

## Контекст

Чистый векторный поиск теряет точные совпадения и хэштеги. Чистый текстовый не
находит ничего на другом языке. Вдобавок у эмбеддингов высокий шумовой пол: при
мягком пороге в выдачу попадает вообще всё, с околонулевыми баллами.

## Решение

Две выборки — `ILIKE` по тексту и косинусное расстояние по pgvector —
объединяются по весам: текстовое совпадение даёт 0.45, семантическое до 0.55.
Порог отсечения — 0.42 косинусного расстояния.

Порог не подобран на глаз. Скрипт `scripts/probe-distance.ts` измеряет
распределение расстояний на реальном корпусе:

| Запрос | Настоящие совпадения | Первый нерелевантный |
|---|---|---|
| `оқу` | 0.35, 0.36 | 0.43 |
| `векторный поиск` | 0.23, 0.33 | 0.43 |
| `design systems` | 0.37 | 0.45 |
| `рецепт борща` (темы нет) | — | 0.47 |

## Последствия

**Хорошее.** На заведомо бессмысленном запросе выдача пустая, а не правдоподобный
мусор. Кросс-языковой поиск работает: `graduated from university` находит
казахский пост без единого общего слова.

**Плохое.** Порог привязан к конкретной модели эмбеддингов. Смена
`AI_EMBEDDING_MODEL` требует повторного замера — об этом сказано прямо в коде
рядом с константой.
