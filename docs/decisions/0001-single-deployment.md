# 0001. Одно развёртывание вместо фронтенда и бэкенда по отдельности

## Контекст

Задание требует «написать бэкенд и интегрировать его с приложением». Очевидный
вариант — отдельный сервер на Fastify или Express рядом с фронтендом. Срок на
реализацию — полтора дня.

## Решение

Одно приложение на Next.js: серверные компоненты и route handlers работают в том
же развёртывании, что и клиентский код.

## Последствия

**Хорошее.** Серверные компоненты ходят в базу напрямую при первой отрисовке —
лента приходит уже с постами, без промежуточного запроса по сети. Одна сборка,
одно окружение, один деплой. Типы общие между клиентом и сервером без публикации
отдельного пакета.

**Плохое.** Приложение привязано к платформе, умеющей запускать Next.js. Если
понадобится мобильный клиент, бэкенд придётся выносить — правда, REST-контракт
для этого уже есть (см. [0002](0002-rest-over-server-actions.md)).

**Что заставило бы пересмотреть.** Второй потребитель API — мобильное приложение
или внешняя интеграция. Тогда слой `lib/queries` переезжает в отдельный сервис, а
роуты становятся тонкой обёрткой над ним.
