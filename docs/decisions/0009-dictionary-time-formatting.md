# 0009. Относительное время из словаря, а не из `Intl.RelativeTimeFormat`

## Контекст

Интерфейс переведён на три языка. Даты и «5 минут назад» до этого форматировал
`Intl.RelativeTimeFormat` — очевидный выбор: правила склонения, локали и
падежи уже в платформе.

При проверке казахского интерфейса в браузере оказалось, что вместо
«15 минут бұрын» выводится `-15 min`, а дата — `2026 M09 16`. Это вывод корневой
локали ICU: в сборке Chromium нет данных для `kk`. Проверка остальных локалей
показала, что `ru`, `en`, `tr`, `pl`, `uk`, `de`, `fr`, `ja` работают —
отсутствует именно казахский, то есть язык, ради которого всё и делалось.

Хуже, чем некрасивый текст: Node на сервере данные для `kk` имеет. Сервер
отрисовывал «15 минут бұрын», браузер при гидратации — `-15 min`, и React
сообщал о расхождении разметки.

## Решение

Формы времени лежат в словарях рядом с остальными строками, а
`src/lib/i18n/time.ts` собирает из них ответ. Выбор формы множественного числа
остаётся за `Intl.PluralRules` — эти данные есть везде, они компактные и
встроены в саму спецификацию.

Названия месяцев тоже в словаре: `Intl.DateTimeFormat` для `kk` деградирует так
же.

## Последствия

**Хорошее.** Сервер и браузер дают посимвольно одинаковый результат — расхождений
гидратации по этой причине быть не может. Казахский выглядит так же, как русский
и английский, независимо от сборки браузера. Формулировки редактируются в
словаре: «вчера» вместо «1 день назад» — это строка, а не флаг форматтера.

**Плохое.** Около шестидесяти строк, которые платформа умеет сама — для языков, где она
действительно умеет. Добавление четвёртого языка теперь требует и месяцев, и
шести форм времени, а не только перевода интерфейса. Часовой пояс для абсолютной
даты берётся из окружения (`Date#getHours`), как и раньше у `Intl`.

**Что заставило бы пересмотреть.** Появление казахских данных во всех целевых
браузерах — но проверять это пришлось бы на каждом релизе, а цена ошибки ложится
на основной язык продукта.
