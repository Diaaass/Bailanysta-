# 0003. Векторы в основной базе, без отдельного хранилища

## Контекст

Для семантического поиска нужно хранить эмбеддинги постов. Обычный выбор —
специализированная база: Pinecone, Qdrant, Weaviate.

## Решение

Колонка `vector(1536)` в таблице `posts`, расширение pgvector, индекс HNSW.

## Последствия

**Хорошее.** Поиск — один SQL-запрос с обычным `JOIN` к авторам и подсчётом
лайков. Нет рассинхрона между двумя хранилищами: пост и его вектор живут в одной
строке и удаляются одной операцией. Нет второго сервиса в окружении и второго
счёта за хостинг.

**Плохое.** На больших объёмах выделенная векторная база даст лучшее время ответа
и больше возможностей настройки. pgvector с индексом по умолчанию рассчитан
примерно на десятки тысяч строк — дальше нужно подбирать `m` и
`ef_construction`.

**Что заставило бы пересмотреть.** Сотни тысяч постов или требование отвечать
быстрее десятков миллисекунд.
