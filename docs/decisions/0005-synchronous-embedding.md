# 0005. Эмбеддинг считается синхронно при записи

## Контекст

Чтобы пост попал в семантический поиск, для него нужен вектор. Вызов модели
занимает в среднем 464 мс, p95 — 759 мс. Естественное решение — очередь и
фоновый обработчик.

## Решение

Вектор считается в том же запросе, что и создание поста, сразу после вставки.
Ошибка индексации не отменяет публикацию: пост сохраняется без вектора и
находится текстовым поиском, пока не отработает `npm run db:embed`.

## Последствия

**Хорошее.** Пост доступен семантическому поиску немедленно. Нет очереди, нет
воркера, нет ещё одного сервиса в окружении.

**Плохое.** Создание поста длится примерно на полсекунды дольше, чем могло бы.

**Почему не фоном.** Serverless-функция замораживается сразу после ответа —
задача, запущенная без `await`, просто не выполнится. Чтобы вынести это в фон,
нужен постоянно работающий процесс, то есть отдельная инфраструктура.

**Что заставило бы пересмотреть.** Рост частоты публикаций или переход на хостинг
с длительно живущими процессами.
